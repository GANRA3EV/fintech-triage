# Fintech Triage

Классификация обращений на русском языке: основная и дополнительная темы,
срочность и краткое резюме. Проект читает XLSX, обучает классификаторы и
сохраняет прогнозы вместе с причинами передачи обращения оператору.

Доступны три варианта признаков:

- **TF-IDF** — работает без загрузки нейросетевых весов.
- **rubert-tiny2** — локальный русский кодировщик с обучаемыми классификаторами.
- **multilingual-e5** — альтернативный кодировщик для текстовых векторов.

Резюме составляется из предложений исходного обращения через `rubert-tiny2`.
Обработка выполняется на CPU. Внешний сервер генерации и ключ API не нужны.

## Быстрый старт

Python 3.11–3.14. Команды ниже рассчитаны на PowerShell и запускаются из папки
репозитория. В Linux и macOS путь к Python окружения — `.venv/bin/python`.

```powershell
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -e ".[dev]"
.\.venv\Scripts\python.exe code/make_demo.py
.\.venv\Scripts\python.exe run_all.py train --input data/synthetic.xlsx --train-end 2025-02-01 --validation-end 2025-03-01
```

Пример создаёт синтетические обращения и обучает TF-IDF-классификаторы.
Полученные метрики подходят для проверки запуска, но не для оценки качества
на реальных обращениях.

## Формат данных

Одна строка XLSX соответствует сообщению. Сообщения одной переписки
объединяются по времени.

| Столбец | Содержание | Когда нужен |
|---|---|---|
| `client_id` | Обезличенный идентификатор клиента | Всегда |
| `conversation_id` | Идентификатор переписки | Всегда |
| `timestamp` | Дата и время сообщения, приводятся к UTC | Всегда |
| `text` | Текст сообщения | Всегда |
| `primary` | Основная тема | Обучение |
| `secondary` | Дополнительная тема, может быть пустой | Обучение |
| `urgency` | `low`, `normal`, `high` или `critical` | Обучение |

Категории и их описания находятся в [categories.json](categories.json).
Для другого набора тем понадобятся собственные категории и размеченные
обращения. В обучающей выборке должны присутствовать все основные темы
и минимум два класса срочности.

## Обучение с RuBERT

```powershell
.\.venv\Scripts\python.exe -m pip install -e ".[local-hf]"
.\.venv\Scripts\python.exe run_all.py train --input data/real.xlsx --output artifacts/rubert --backend rubert --train-end 2025-02-01 --validation-end 2025-03-01
```

Используется [cointegrated/rubert-tiny2](https://huggingface.co/cointegrated/rubert-tiny2),
ревизия `e8ed3b0c8bbf4fb6984c3de043bf7d2f4e5969ae`. При первом запуске
скачиваются веса, затем используется локальный кэш Hugging Face.

Веса кодировщика заморожены. На его векторах обучаются логистические регрессии
для темы и срочности, а также классификатор набора тем. Длинные тексты
разбиваются на окна по 512 токенов с перекрытием 64 токена. Векторы окон
усредняются и нормируются.

Для multilingual-e5 доступен набор зависимостей `.[embeddings]` и параметр
`--backend e5`. TF-IDF выбирается через `--backend tfidf` и используется по
умолчанию.

## Прогноз и резюме

```powershell
.\.venv\Scripts\python.exe run_all.py predict --model artifacts/rubert/model.joblib --input data/incoming.xlsx --output artifacts/incoming.xlsx --with-summary
```

Для прогноза разметка тем и срочности не нужна. Флаг `--with-summary` добавляет
до трёх предложений из исходного текста, суммарно до 800 символов. Новые
формулировки и произвольные поля не генерируются. При ошибке резюме остаётся
пустым, а ответ содержит класс ошибки. Старое имя флага `--with-llm` сохранено
для совместимости.

В прогнозе есть оценки уверенности, `operator_review` и список причин
`review_reasons`. Критическое обращение всегда направляется оператору.
Программа не выполняет финансовых операций.

## Оценка качества

### Сравнительное исследование

```powershell
.\.venv\Scripts\python.exe -m pip install -e ".[research,local-hf]"
.\.venv\Scripts\python.exe code/make_demo.py
.\.venv\Scripts\python.exe run_all.py study --input data/synthetic.xlsx --config config/research.json --output articles/ticket_demo
```

Сценарий один раз подготавливает данные и фиксирует общие временные выборки.
Частотный классификатор, TF-IDF и RuBERT запускаются в отдельных процессах.
Для e5 нужно установить `.[embeddings]` и добавить `e5` в `backends`.
Ревизии обоих кодировщиков закреплены. Ошибка одного варианта сохраняется
в журнале; остальные продолжают работу. При любом неуспешном варианте
команда возвращает код 1. Существующая папка результатов не перезаписывается.

Конфигурация задаёт временные границы, варианты, seed и число повторений
bootstrap. В примере указан `data_kind: synthetic`. Для реального корпуса
нужно изменить отметку и временные границы до запуска эксперимента.

В `articles/ticket_demo/` сохраняются папки `article`, `data`, `tables`,
`figures`, `code`, `references`, `logs`, `kb_context`. Таблица
`tables/comparison.xlsx` содержит сопоставимые метрики, матрицы ошибок и
парные 95% интервалы разности Macro-F1. Повторная выборка выполняется
по клиентам тестовой части. Модели при расчёте интервалов не переобучаются.
Интервалы не учитывают неопределённость обучения и смену временного периода.

Время обучения включает первое получение признаков и загрузку кодировщика.
Прогноз измеряется на прогретой модели. RSS текущего процесса измеряется
каждые 10 мс; короткие пики и дочерние процессы могут не попасть в оценку.
Результаты синтетического примера подтверждают выполнение сценария.
Критические случаи, отсутствующие в тестовой части, получают пустую метрику
полноты, без подстановки нуля. Macro-F1 срочности считается по четырём
фиксированным классам, включая отсутствующие, с нулевым вкладом таких классов.

Подбор порога учитывает правила передачи критических обращений оператору.
Доля без дополнительной проверки относится к флагу `operator_review`;
окончательное подтверждение оператором остаётся обязательным для всех обращений.

Обучение, подбор порога и тестирование разделены по времени. Клиенты из
обучения исключаются из проверочной и тестовой выборок. Переписки, пересекающие
временную границу, исключаются. Точные дубликаты удаляются; противоречивая
разметка отклоняется.

TF-IDF обучается только на обучающей выборке. Порог уверенности подбирается на
проверочной выборке. Если подходящий порог не найден, все обращения передаются
оператору. В `metrics.json` сохраняются macro-F1 тем и срочности, доля обращений
для проверки и число исключённых записей. Вероятности не калиброваны.

## Результаты

В папке, заданной через `--output`, после обучения сохраняются:

| Файл | Содержание |
|---|---|
| `model.joblib` | Классификаторы, категории и порог |
| `predictions.xlsx` | Прогнозы на тестовой выборке |
| `metrics.json` | Метрики и результаты подбора порога |
| `diagnostics.json` | Типы полей и пропуски |
| `descriptive_statistics.xlsx` | Длина текстов по категориям |
| `split_manifest.xlsx` | Принадлежность записей выборкам |
| `run_manifest.json` | Параметры, версии библиотек и контрольные суммы |

Очистка скрывает распространённые контакты и цифровые идентификаторы, но
не заменяет полное обезличивание. Исходные обращения и веса исключены из Git.
Файлы `joblib` следует загружать только из доверенного источника.
