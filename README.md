# Обработка обращений финтех-сервиса

Проект классифицирует обращения по основной и дополнительной темам, оценивает срочность и готовит черновик резюме. Финансовые действия отсутствуют. Оператор подтверждает каждое действие.

## Запуск

Python 3.11–3.14. Выполняйте команды из папки проекта. Проверенные версии зависимостей для Windows и Python 3.14 сохранены в `requirements-tested.txt`.

```powershell
python -m venv .venv
.venv/Scripts/python -m pip install -e '.[dev]'
.venv/Scripts/python code/make_demo.py
.venv/Scripts/python run_all.py train --input data/synthetic.xlsx --train-end 2025-02-01 --validation-end 2025-03-01
.venv/Scripts/python -m pytest -q
```

Синтетический набор предназначен для проверки запуска. Значения качества на нём не характеризуют реальные обращения. Показатели 0,71, 0,84, 97% и сокращение времени обработки из постановки задачи не воспроизведены: исходные данные отсутствуют.

## Входные данные

XLSX со столбцами `client_id`, `conversation_id`, `timestamp`, `text`, `primary`, `secondary`, `urgency`. Идентификаторы должны быть предварительно обезличены. Время приводится к UTC. Разрешены `low`, `normal`, `high`, `critical`. Дополнительная тема допускает пустое значение. Названия 12 категорий и их описания в `categories.json` предложены для примера и требуют согласования с предметными специалистами.

Сообщения одной переписки объединяются по времени; переписки с противоречивой разметкой отклоняются. Пустые тексты и точные дубликаты удаляются. Переписки, пересекающие временную границу, исключаются. Клиенты из обучения удаляются из validation и test; клиенты из validation удаляются из test. Такое правило уменьшает выборку и меняет состав клиентов, поэтому число исключений сохраняется отдельно. Приближённые дубликаты пока не удаляются.

До обучения сохраняются типы полей, пропуски, распределение длины по категориям. Длина текста служит описательной диагностикой; автоматическое удаление длинных обращений не применяется. Корреляции идентификаторов не рассчитываются. TF-IDF обучается только на train. Основная тема и срочность используют отдельные логистические регрессии, дополнительная тема определяется классификатором нескольких меток. Возможны максимум две темы.

Порог выбирается по validation с целевой точностью основной темы и срочности 0,9 среди принятых обращений. При отсутствии подходящего порога все обращения направляются на проверку. Порог дополнительной темы фиксирован на 0,5. Вероятности не калиброваны; оценка на малой выборке имеет высокую неопределённость. Тестовая выборка не участвует в подборе порога.

## Эмбеддинги

```powershell
.venv/Scripts/python -m pip install -e '.[embeddings]'
.venv/Scripts/python run_all.py train --input data/real.xlsx --output artifacts/e5 --backend e5 --train-end 2025-02-01 --validation-end 2025-03-01
```

multilingual-e5 получает префикс `query: ` и нормированные векторы. Первая загрузка требует сети. Длинные переписки ограничиваются допустимой длиной входа модели; для промышленного применения нужна проверка разбиения длинных текстов на части. Для строгого повторения эксперимента закрепите ревизию весов и сохраните `pip freeze`.

## Локальная модель Hugging Face и машинное обучение

Вызов Qwen удалён. Используется русский кодировщик
[cointegrated/rubert-tiny2](https://huggingface.co/cointegrated/rubert-tiny2)
с ревизией `e8ed3b0c8bbf4fb6984c3de043bf7d2f4e5969ae`.
Вычисления выполняются на CPU. Первая загрузка весов требует сети; последующие
запуски используют кэш Hugging Face. Сервер генерации и ключ API не нужны.

```powershell
.venv/Scripts/python -m pip install -e '.[local-hf,dev]'
.venv/Scripts/python run_all.py train --input data/real.xlsx --output artifacts/rubert --backend rubert --train-end 2025-02-01 --validation-end 2025-03-01
.venv/Scripts/python run_all.py predict --model artifacts/rubert/model.joblib --input data/incoming.xlsx --output artifacts/incoming.xlsx --with-summary
```

Обучаются логистические регрессии основной темы и срочности; дополнительная
тема определяется классификатором нескольких меток. Вариант `rubert` получает
нормированные векторы CLS от закреплённого кодировщика. Его веса заморожены;
обучаются классификаторы. Длинные тексты делятся на окна по 512 токенов с
перекрытием 64 токена. Векторы окон усредняются и нормируются повторно.
Объединение окон предложено в коде проекта и требует оценки на предметном
корпусе. TF-IDF сохранён для сравнения при одинаковом разбиении данных.
Метрики и порог по validation сохраняются штатной командой `train`.

Резюме выбирает максимум три исходных предложения по близости к среднему
вектору предложений и ограничивается 800 символами. Порядок фрагментов
сохраняется. Новые формулировки не генерируются; поле `fields` остаётся пустым.
Каждый фрагмент проверяется на дословное присутствие в тексте. Полноту
сокращения оценивает оператор. При ошибке возвращаются пустой черновик и класс
ошибки. Старый флаг `--with-llm` оставлен как совместимое имя локального резюме.

```powershell
$env:TEST_LOCAL_HF = '1'
.venv/Scripts/python -m pytest -q tests/test_local_hf.py
```

Очистка регулярными выражениями удаляет адреса электронной почты и распространённые цифровые идентификаторы. Имена, адреса, нестандартные номера и сведения внутри свободного текста могут сохраниться. Используйте предварительно обезличенные данные. Данные, веса и отчёты исключены из Git. Загружайте `joblib` только из доверенного источника.

## Результаты запуска

Для отдельной ручной проверки резюме выполните `python code/evaluate_llm.py --input data/llm_holdout.xlsx --output artifacts/llm_eval`. Нужен столбец `text`. Сценарий сохраняет долю прошедших проверку ответов и XLSX для оценки смысловой точности и полноты оператором.

В `artifacts` сохраняются `diagnostics.json`, `descriptive_statistics.xlsx`, `split_manifest.xlsx`, `metrics.json`, `predictions.xlsx`, `model.joblib`, `run_manifest.json`. Результаты включают macro-F1 основной темы, набора тем и срочности, долю направленных на проверку и статистику исключений. Исходный файл контролируется SHA-256. Прогнозы содержат хэш текста, без исходного сообщения и идентификатора клиента.

## Версии и GitHub

Версия пакета — 0.3.0. История изменений находится в `CHANGELOG.md`; GitHub Actions запускает тесты на push и pull request. Коммиты не должны содержать реальные обращения или секреты. Для публикации нужен доступ к выбранному репозиторию GitHub.

| Версия | Содержание |
| --- | --- |
| v0.1.0 | Первый рабочий цикл обработки и обучения |
| v0.1.1 | Проверка параметров и пустых пакетов |
